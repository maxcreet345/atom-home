# Архитектура Atom Home

## Принципы
1. **Один код — много домов.** Панель не знает конкретных сущностей. Всё, что отличает дом, лежит в `HouseConfig` (JSON) и в реестре самого HA.
2. **HA — источник правды.** Комнаты из зон (areas), устройства из реестра устройств, состояния из `hass.states`. Панель только читает реестр и состояния, команды — через `callService`.
3. **Автоматическое распознавание + ручная правка.** `discover()` строит модель дома из реестра по доменам и `device_class`; `HouseConfig` накладывает правки: показать/скрыть, имя, комната, значок, объединение, порядок.
4. **Честность.** Неизвестное — «нет данных», а не ноль. Команда считается выполненной только по изменению состояния; «принято HA» и «физически сработало» — разные вещи.
5. **Безопасность.** Типовые действия по белому списку на вид устройства; произвольные сервисы только через конструктор кнопок с явным флагом подтверждения; опасные (кран, замок, сброс) — всегда с подтверждением. Никаких токенов в панели: используется сессия HA.

## Слои
```

              config.ts     схема HouseConfig v1, валидация, значения по умолчанию, слияние
  runtime/    host.ts       мост к hass: состояния, реестр по WS, callService, история/статистика
              actions.ts    белый список действий по виду + кнопки-сервисы, подтверждения, наблюдение результата

  ui/         экраны и карточки (дизайн-система V18): Обзор, Комнаты, Свет, Климат, Уборка, Энергия, Системы, Камера, Погода, Конфигуратор
```

## Оболочка: команды, адреса, загрузка (аудит 09.11.2026)
**Команды.** Всё, что уходит в дом, идёт через один исполнитель (`runtime/commands.ts`, в `app.tsx` это `commands`):
- пока дома нет на связи, ничего не отправляется, человек видит «Нет связи с домом»;
- вторая такая же команда, пока первая в пути, не отправляется (двойное касание даёт одну команду);
- плитка «дышит», пока команда в пути; переключатель ждёт, пока придёт новое состояние (не дольше 3 с);
- отказ показывается предложением на языке панели: `errorText(e, t)` из `ui/format.ts` понимает `Error`, объект HA `{code, message}`, коды потери связи, строку и что угодно ещё. Слова HA цитируются только там, где HA писал их для людей (`service_validation_error`, `home_assistant_error`); текст разборщика и «[object Object]» на экран не попадают.

Карточки получают `host`, у которого `call` уже идёт через этот исполнитель, и могут брать сам исполнитель (`commands.run(key, work, { onError })`), если ведут свою строку ошибки. Переключатель отправляется как `turn_on` / `turn_off` по показанному состоянию, не `toggle`: повторное касание до прихода состояния не возвращает лампу обратно.

**Опасное спрашивает.** Кроме крана, замка и охраны, вопрос задаётся перед «выключить всё» (кнопка-сервис `turn_off` на несколько целей, что бы ни стояло в её флажке) и перед любой настройкой самого прибора в листе («Detach relay mode», «Power-on behavior», кнопка перезагрузки). Настройки прибора видит только администратор. Вопрос закрывается по «Назад», при переходе на другую страницу и когда прибор пропал со связи; под вопросом всё остальное недоступно с клавиатуры.

**Адреса и «Назад»** (`runtime/route.ts`). Новая страница открывается с начала, «Назад» возвращает место прокрутки и плитку, с которой ушли. Закрытие листа, кнопки «Комнаты» и «Пылесос» со стрелкой назад делают шаг назад по истории, если предыдущая запись и есть цель (иначе текущая запись заменяется): «Назад» никогда не открывает только что закрытое, три открытия и закрытия не копят записей. Переключатели внутри страницы («Обзор / Сейчас», «Внимание») записей не добавляют. Адрес, который ничего не называет (старая закладка, скрытый раздел, пропавшая комната или прибор), заменяется ближайшим настоящим. При переходе из содержимого фокус получает заголовок страницы.

**Объявления.** У оболочки две живые области: спокойная (`role=status`: «Связь с домом восстановлена») и срочная (`aria-live=assertive`: «Нет связи с домом», тревога модуля, звонок, отказ команды; её видимая часть и есть всплывающее сообщение). Каждое событие произносится один раз.

**Загрузка и настройки** (`live-main.tsx`). Реестр и настройки читаются отдельно, неудачное чтение повторяется само (2 с, 5 с, 15 с, далее каждые 30 с); на экране заготовка с фразой на языке панели, а не текст ошибки. Если не прочитались настройки, дом показывается на заводских с пометкой «Настройки дома ещё не загружены» и **ничего не сохраняет**: `ha-store` отказывает в `config/set` и `alarms/set` (`save.error.not_loaded`), пока `config/get` не ответил хотя бы раз. Иначе заводской набор без ревизии затёр бы настоящие настройки. Пока запись интеграции перезагружается (или выключена), сервер отвечает на `config/get` ошибкой `not_loaded`, а не «`config: null, revision: 0`»: для панели это неудачное чтение — она оставляет то, что уже показывает, и повторяет его; пустой ответ с ревизией 0 означает только дом, в котором ещё ничего не сохранено. Реестр перечитывается по событиям HA (`entity/device/area/floor_registry_updated`, пачка событий даёт одно чтение), раз в час для страховки и после возврата связи; настройки раз в 5 минут и после возврата связи.

**Перерисовка.** Пачка изменений состояний даёт одну отрисовку в кадр; `hass`, в котором не изменились ни состояния, ни связь, ни пользователь, не рисуется. Модель дома (`rememberDiscover` в `model/discover.ts`) отвечает из памяти: состояние, не меняющее состав дома, обновляет только карточки, где оно стоит; состав пересчитывается, когда меняется реестр, настройки или «форма» состояния (имя, класс, единица, появление сущности).

### Оболочка после второго круга аудита (10.11.2026)
**Место клавиатуры** (`ui/focus-keep.ts`). Одна сетка на всю оболочку: наблюдатель за атрибутом `disabled` на корне панели и последний сфокусированный элемент (`focusin`, с учётом теневого корня — фокус берётся у `getRootNode().activeElement`). Кнопка, которая на время команды стала `disabled` и уронила фокус на `body`, получает его обратно, как только освободится и если фокус всё ещё нигде; если человек ушёл фокусом в другое место или кнопка исчезла — про неё забывают. Возврат фокуса после листа и вопроса идёт через ту же сетку (`keep.give`). Карточкам на время ожидания лучше ставить `aria-disabled` + `aria-busy` (фокус не теряется вовсе), сетка страхует оба способа.

**Стрелки пульта** (`ui/spatial-nav.ts`). ←↑→↓ переводят фокус на ближайший по геометрии элемент верхнего слоя (всё, что не под `inert`: вопрос → лист → страница с меню и баннерами). Сначала соседи в той же строке или колонке, потом ближайший по расстоянию; найденный элемент прокручивается в поле зрения. Не перехватываются: клавиша, которую уже обработали (`defaultPrevented` — график энергии, свои меню карточек), клавиша с модификатором, поле ввода, `select`, ползунок (`role=slider`, `input[type=range]`). Нет соседа в эту сторону — ничего не делается, страница прокручивается как раньше. Кто последним нажимал мышью или пальцем, тому стрелки оставлены для прокрутки (до первого Tab); у телевизора стрелки работают всегда. Геометрия — чистая функция `nearest(from, boxes, dir)`.

**Тревога поверх всего** (`ui/shell-banner.tsx`, `shellAlarm` в `model/security-words.ts`; выпуск «classic» 11.11.2026). Тревога, газ или дым, протечка и задержка на вход занимают экран сверху над любой страницей и любым листом (`Takeover`, тёмно-красная карточка в цветах нынешних тем), словами плитки «Безопасность»; у задержки идёт отсчёт (`role=timer`, вне живой области, по часам дома — `delayClock`). Одно главное действие высотой 56 px по причине: тревога и задержка — «Снять с охраны» (через исполнитель команд и с подтверждением, без связи — «Нет связи с домом»); протечка при открытом кране — «Перекрыть воду» одним касанием; газ, дым, кран уже закрыт — «Показать». Рядом «Показать» (`#security`). На самой странице «Безопасность» без листа тревоги нет — страница говорит то же. Escape и «Назад» закрывают листы и вопросы, тревогу — нет. Текст (`announcement`, включая вскрытие корпуса) попадает в срочную живую область один раз. Тревога, звонок в дверь (когда открыт другой лист) и уведомление модуля (таймер, будильник) стоят одной колонкой (`Banners`) в этом порядке; колонка ничего не закрывает: рельс, страница и лист начинаются под ней (`--ah-banners-h`). Главное действие появившейся колонки — следующая остановка Tab; если фокуса нет нигде и человек работает с клавиатуры или пульта, фокус встаёт на него; у поля ввода фокус не отнимается. Офисная охрана (`officeSec`) не затронута.

**Строка состояния дома** (`model/house-status.ts` решает, `ui/house-status.tsx` рисует; выпуск «classic»). Над карточками «Дома» (их порядок и раскладка прежние) одна строка: «Всё в порядке» или «Нужно внимание: N» и по чипу на каждую проблему — тревога, задержка, газ, дым, протечка, нет связи с домом (красные), открыто при охране, окно при отоплении, давление котла, отопление без связи, приборы без связи (группой), садящиеся батареи, пылесос (жёлтые); чип открывает своё место («Безопасность», «Климат», лист прибора, «Устройства → Внимание», «Уборка»), никогда — скрытую страницу.

**Баннер будильника и таймера.** «Стоп» и «Ещё 9 минут» идут через исполнитель команд (`banner:stop`, `banner:snooze`): без связи ничего не уходит, второй раз не отправляется, отказ виден во всплывающем сообщении, кнопка на время ожидания `aria-busy`.

**Вопросы.** Без связи вопрос не открывается: сразу «Нет связи с домом». Текст и подписи кнопок собирает `confirmWords` (`ui/shell-logic.ts`): открытие крана при мокром датчике протечки — из любого места — называет протечку, первая кнопка «Оставить закрытым». Системная «Назад» при открытом вопросе закрывает только вопрос (`stayOn` в `runtime/route.ts` возвращает запись, с которой браузер ушёл). «Выполнить», пока у того же устройства в пути другая команда, ждёт её (до 6 с, кнопка `aria-busy`), а не молчит.

**Адреса.** Адрес пишется без `URLSearchParams.size` (Safari ≤ 16, Chromium ≤ 112 его не знают — комнаты и листы там не открывались). Два закрытия листа в один тик дают один шаг назад. Закрытие листа сохраняет `filter` страницы. Холодный `#nonsense` сразу становится `#home`. Пока настройки дома не прочитаны (`configPending`), адрес не чинится: лист модуля или раздел, которые появятся с настоящими настройками, откроются после чтения.

**Настройки.** Перечитывание после звонка будильника принимает настройки целиком вместе с ревизией (раньше — только список будильников, и следующее сохранение стирало чужую правку). Значение, которое панель ещё сохраняет, не считается подтверждённым, даже если пришло обратно свойством от родителя: при отказе панель возвращается к последнему сохранённому. Ответ `not_loaded` (запись интеграции перезагружается) — неудачное чтение: панель держит то, что есть, и читает снова; пустой ответ старой интеграции после успешного чтения считается тем же самым.

**Сообщения.** Всплывающее сообщение живёт не меньше 6 с, длинное — дольше (до 20 с), стоит, пока на нём указатель или фокус клавиатуры (на него можно попасть Tab или стрелкой; Enter, пробел, Escape закрывают). «Нет связи с домом» исчезает с возвращением связи и в живую область попадает одной строкой. «Нужен перезапуск Home Assistant» после сообщения остаётся значком в шапке у администратора.

**Размер.** Экран с касанием (`navigator.maxTouchPoints > 0`) телевизором не считается при любой ширине: киоск 1920×1080 рисуется 1:1. Телевизор — нет наведения, нет касаний и нет указателя вовсе либо ширина от 1800 px.

**Отрисовка.** Активные модули ищутся заново только когда меняется то, от чего они зависят: списки реестра, настройки, появление или пропажа состояния, его класс, имя, единица и набор атрибутов (`runtime/remember-modules.ts`); смена значения поиска не стоит. Исполнитель команд сообщает оболочке о «занятости» только при смене набора ключей. Пустые живые области не переписываются. `measure()` не рисует при том же округлённом размере. Аудиоконтекст по первому касанию не создаётся — его делает `beep()`, когда звук действительно нужен.

## Модель устройства (`Home`)
- `Room {id, name, photo?, hidden}` — из `area_registry`; устройства без зоны попадают в комнату `none` («Без комнаты»).
- `Device {key, kind, name, roomId, primary: EntityRef, entities: EntityRef[], metrics, parameters, diagnostics, actions, available, enabled}` — один прибор HA (по `device_id`) или одиночная сущность без устройства. `kind` определяется по главной сущности (приоритет: climate → light → vacuum → media → camera → cover → lock → fan → switch → sensor…). Датчики температуры/влажности/CO₂ одного прибора объединяются в одно устройство вида `environment`; мощность/энергия/напряжение — `energy`.
- Служебные сущности (категории `diagnostic`/`config`, домены update, automation, input_*, zone, sun, tts, stt, conversation, event, todo, calendar, notify) не становятся карточками: `config` → параметры устройства, `diagnostic` → диагностика.
- Объединение розетки с прибором — через `HouseConfig.devices[key].mergeInto`.

## HouseConfig v1 (JSON)
```
{ schemaVersion: 1,
  home: { name, logo?, language: 'ru'|'ro'|'en', theme: 'light'|'dark' },
  rooms: { [areaId]: { name?, photo?, hidden?, order? } },
  devices: { [deviceKey]: { enabled, name?, roomId?, icon?, kind?, mergeInto?, order? } },
  entities: { [entityId]: { hidden?, name? } },
  buttons: [ { id, label, icon?, roomId?, service: 'domain.service', target?, data?, confirm } ],
  sections: { [screen]: { hidden? } } }
```
Без конфигурации панель показывает все бытовые устройства во всех зонах — это и есть «первая установка», после которой владелец убирает лишнее.

## Сведение аудита 10.11.2026
- **Версия панели и интеграции.** Сборка пишет версию из `manifest.json` в бандл (`vite.live.config.ts` → `__ATOM_VERSION__`, атрибут `data-atom-version` на элементе панели). Ответ `atom_home/config/get` несёт версию работающего Python: `manifest.json` читается один раз за запуск Home Assistant (`_RUNNING_VERSION`), перезагрузка записи без перезапуска версию не меняет, и напоминание не гаснет, пока старый код в памяти. Если они разные (обновили через HACS, Home Assistant не перезапускали), администратор один раз видит «Atom Home обновлён: нужен перезапуск Home Assistant» (`runtime/store.ts: restartNeeded`). Порядок выпуска поэтому: сначала версия в манифесте, потом `npm run build` — `scripts/qa-integration.mjs` (раздел 10) проверяет, что бандл в репозитории собран под версию манифеста.
- **Часовой пояс дома** — `runtime/zone.ts`, см. docs/CLOCK.md.
- **Живая область оболочки** называется `.hm-announce` (класс `.hm-live` — только значок LIVE у камер).
- **Раздача файлов.** `/atom_home_static/assets` (картинки с хешем в имени) отдаётся с долгим кешем, сам каталог `/atom_home_static` — без кеша; минимальная версия Home Assistant в `hacs.json` — 2024.7.0 (нужна `async_register_static_paths`). Текст заглушки загрузчика — на языке, который панель оставила в `localStorage['atom-home-lang']`, иначе на языке Home Assistant или браузера.
- **Один шлюз на весь дашборд:** `frontend/scripts/gate-full.sh <папка>` — типы, `npm test`, тесты бэкенда под местным python3, обе сборки и все `qa-*.mjs` по очереди (кроме `qa-live`: ему нужен настоящий HA); по строке на шаг и в конце `GATE: clean` или `GATE: FAILED <имена>`. Список шагов после папки запускает только их.
