# Доступ по зданиям (1.43.0, 27.11.2026)

Владелец решил разделить доступ **только в интерфейсе**. Групп и политик Home Assistant для этого нет, отдельного HA на каждое здание тоже нет. Администратор сам назначает в «Настройке → Доступ» («Acces»), кто к какому зданию относится и что там видит.

> Это разделение интерфейса Atom Home. Приложение HA, история и журнал по-прежнему показывают всё. Сервер ничего не проверяет: `config/get` отдаёт настройки всем, а команды Home Assistant принимает от любого вошедшего пользователя.
> Старые дашборды и боковое меню HA лучше скрыть через `kiosk-mode.js`. Тогда сотрудник не уйдёт из панели в обычный интерфейс HA.

## Что чем считается
- **Здание** — это этаж Home Assistant (floor registry). **Комнаты здания** — зоны (areas) этого этажа. Панель их только читает; переименовать здание или перенести зону можно только в HA, в разделе «Настройки → Зоны».
- **Зона без этажа** (например, «Двор») не принадлежит ни одному зданию. Во вкладке она стоит отдельно с пометкой «Без здания». Её видят только люди с переключателем «Все здания» и администраторы.
- **Роль** — это шаблон. В ней задаются:
  - название;
  - разделы: свет, устройства, климат, уборка, камеры, энергия, безопасность. «Обзор» и «Комнаты» есть в любой роли;
  - карточки:
    - `cameras` — камеры и звонок;
    - `security` — Alarmo и «Безопасность»;
    - `energy` — «Энергия»;
    - `clock` — таймеры и будильники; без этой карточки на главной остаются простые часы;
    - `climate` — «Климат» и котёл;
  - режим управления:
    - `full` — всё;
    - `lights` — только свет, выключатели и розетки;
    - `view` — только просмотр, кнопок нет.
- **Готовые роли.** Их можно править и копировать, а удалять — пока остаётся хотя бы одна роль.

  | Роль | Режим | Разделы | Карточки |
  |---|---|---|---|
  | Управляющий | full | все | все |
  | Сотрудник | full | свет, устройства, климат | часы, климат |
  | Охрана | full | свет, устройства, камеры, безопасность | камеры, охрана, часы |
  | Планшет | lights | свет, климат | часы, климат |
  | Гость | view | — | — |

  Пустое `name` значит, что название берётся из словаря панели на её языке (`access.role.<id>`).
- **Человек** — это пользователь Home Assistant из `config/auth/list`; системные пользователи (`system_generated`) не показываются. У человека есть:
  - переключатель «Все здания» с одной ролью на все здания, включая зоны без этажа;
  - или своя роль для каждого здания; без роли в здании — «Нет доступа»;
  - необязательная дата «Доступ до» — последний день по календарю дома (`dayKey(houseDate())`), включительно.
- **Администратор** HA (`is_admin`, владелец или группа `system-admin`) всегда видит всё. Ему нельзя выбрать роль, и запереть его нельзя. Вместо выбора роли у него метка «Администратор — видит всё».
- **Планшет** — это названный экран дома, то есть профиль раскладки из `layouts.py` (`atom_home.layouts`). Ему можно назначить здание и роль. На этом экране такое назначение главнее роли того, кто вошёл. Исключение — администратор: он видит всё. Экран узнаёт себя по `atom-home:layout-device` в браузере. Привязка только **меняет роль** в своём здании и сужает экран до него — и только для того, у кого это здание уже есть. Выбрать названный экран в «Расставить» может любой житель, поэтому чужое здание привязка не открывает, и закончившийся доступ на таком экране тоже закончен. Отдельный аккаунт планшета (tableta) нужно внести в «Люди» с доступом к его зданию; стартовый вариант делает это сам.
- **«Кому видно»** — поле устройства во вкладке «Устройства». Варианты: «Всем, у кого есть комната» или «Только ролям…». Метка HA `atom_home_ne_pokazyvat` работает, как прежде.

## Где хранится
В той же конфигурации дома. Запись идёт через `atom_home/config/set` с `expected_revision` и разрешена только администраторам.

```json
"access": {
  "enabled": true,
  "newUsers": "none",              // или "default": тогда defaultBuilding + defaultRole
  "defaultBuilding": "contabilitate", "defaultRole": "guest",
  "roles":    { "staff": { "name": "", "sections": ["lights", "systems", "climate"], "modules": ["clock", "climate"], "mode": "full" } },
  "members":  { "<user_id>": { "all": true, "role": "staff" },
                "<user_id>": { "buildings": { "contabilitate": "staff", "office": "guest" }, "until": "2026-12-31" } },
  "profiles": { "planshet-buh": { "building": "contabilitate", "role": "tablet" } }
},
"devices": { "d:<id устройства HA>": { "roles": ["manager"] } }
```

- Если раздела `access` нет, панель ничего в конфигурацию не добавляет: дом, где вкладку не открывали, сохраняет то же, что и раньше.
- Экспорт и импорт JSON переносят `access` и `roles` без изменений. Это проверяет `tests/access.test.ts`.
- **Сервер.**
  - `config_state.check_access` проверяет форму `access`: объект, `enabled` типа bool, не больше 32 ролей, 500 людей и 64 экранов.
  - `has_access` и флаг клиента `access_v1` не дают панели 1.42.0 и старше молча стереть `access` и `roles` при сохранении. Она получает `client_outdated`.
  - Тесты: `tests/components/atom_home/test_config_guard.py` → `AccessGuard`.

## Как панель применяет разделение
Правила собраны в одном месте — `frontend/src/model/access.ts`. Это чистые функции, их проверяет `tests/access.test.ts`. В оболочке их применяет `ui/access-gate.tsx` — обёртка над всей панелью (`AtomApp`).

- **Разделение выключено** (`enabled: false`, по умолчанию) или **смотрит администратор.** Панель получает ровно то же, что и до 1.43.0: тот же реестр, те же настройки и тот же host.
- **Иначе панель получает:**
  - **Реестр разрешённых зданий** (`scopeRegistry`):
    - зоны и этажи этих зданий;
    - сущности, чья комната в них. Комната определяется сначала переносом владельца в «Устройствах», потом зоной HA;
    - всё, у чего нет комнаты: погода, люди, солнце, помощники часов, общие счётчики дома, Alarmo. В настоящем доме у Alarmo есть устройство без комнаты, и «Охрана» должна его видеть. Карточки таких устройств («Без комнаты») показывает только администратор — их убирает второй проход;
    - без камер, если в роли нет `cameras`, и без панелей охраны, если в роли нет `security`. Камера и панель уходят вместе со всем своим устройством: иначе её выключатель приватности или датчик движения стали бы отдельными плитками;
    - без устройства, у которого «Кому видно» (ключ `d:<id>`) не включает эту роль.

    Поэтому сводки на главной считаются только по разрешённым зданиям: «Всё в порядке», счётчик света, плитка энергии, климат, тревоги. Строки реестра остаются теми же массивами, пока не изменились реестр, область или настройки устройств (`rememberScope`), поэтому смена состояния дом заново не строит.
  - **Второй проход по модели дома** (`deviceShown`). Он ловит то, что знают только настройки: карточку, перенесённую в комнату; карточку каталога; ключ группы датчиков; «Кому видно» одной карточки (`e:<сущность>` — устройство при этом не перестраивается, его датчики не всплывают отдельной карточкой); карточки «Без комнаты» (кроме погоды).
  - **Настройки для рисования** (`scopeConfig`). Разделы и карточки, которых нет в ролях, скрыты (`sections.*.hidden`, `modules.*.enabled: false`). Кнопки владельца, которые здесь нажать нельзя, убраны. Будильники комнат других зданий не показываются. Эти настройки никогда не сохраняются.
  - **Политику управления** (`controlPolicy` → `setControlPolicy` в `runtime/actions.ts`).
    - `actionsFor` и `entityActions` для запрещённого возвращают пусто. Поэтому плитки, листы, строки света и быстрые действия комнаты не рисуют выключателей, ползунков и кнопок.
    - Управление определяется ролью здания, в котором комната устройства. Для того, что не принадлежит ни одной комнате, берётся самый широкий режим среди показанных зданий.
    - Панели со своими кнопками — охрана (дом и офис), отопление и его комнаты, климат офиса, пылесос, таймеры часов, лист света — получают класс `is-readonly` (`readOnlyClass`). Их показания остаются, кнопки, переключатели и поля не рисуются; остаётся только то, что открывает панель.
    - «Выключить весь свет» выключает только лампы, которые здесь можно переключать. Если таких нет, кнопки нет.
    - Запасной заслон — `host.call` и запись через `host.ws` (вызов службы, правка реестра, «Выключить через», задачи «Воздуха», кормушка): запрещённая команда не уходит, а человек видит «Здесь только просмотр — команда не отправлена». Чтение (история, статистика, журнал, видео) и «Стоп» / «Отложить» звонящего будильника проходят.
    - **Исключения.** Листы приборов-модулей (чайник, кормушка, «Воздух», медиа) свои кнопки не прячут. В режиме `view` или `lights` их команды отклоняет заслон с этим сообщением. Роль без нужной карточки или раздела этих листов не видит вовсе.
  - **Хранилище, которое сохраняет только будильники.** Список при сохранении сливается с будильниками других зданий в том виде, в каком они лежат в доме (`mergeAlarms`). Полное сохранение настроек отклоняется. Будильник можно поставить только в разрешённой комнате: окно часов предлагает только комнаты этих зданий.
- **Переключатель зданий** стоит в шапке и появляется, только если зданий несколько. В нём есть «Все здания». Последний выбор запоминается на устройстве (`atom-home:building`). При первом входе выбирается первое здание в порядке HA: уровень, затем имя.
- **Нет доступа ни к одному зданию.** Вместо панели спокойный экран «Доступ ещё не назначен — обратитесь к администратору» (или «Срок доступа закончился»).
- **Экран, который уже был ограничен, это помнит** (`atom-home:access-narrowed`). Пока настройки дома не прочитаны, на нём «Загружаю настройки доступа…». Заводские настройки разделения не знают, и без этого на мгновение показалось бы всё.
- **«Посмотреть глазами»** открывает главную так, как её видит выбранный пользователь. Сверху полоса «Вы смотрите как X · Выйти». «Выйти» возвращает на вкладку «Доступ».

## Безопасное включение
- По умолчанию разделение выключено, и поведение панели прежнее.
- Переключатель «Разделение по зданиям» сначала спрашивает подтверждение. Стартовый вариант: всем текущим пользователям, кроме администраторов, роль «Сотрудник» во всех зданиях (`starterAccess`). Так никто не теряет панель внезапно. Уже заданные записи остаются. Включить разделение можно только после того, как список пользователей HA прочитан.
- Настройка «Новые пользователи видят»: «Ничего» (по умолчанию) или «Здание по умолчанию» с ролью. Новым считается пользователь, которого нет в `members`.
- Если удалить роль, люди и экраны с ней теряют это здание. Другая роль им вместо удалённой не подставляется (`withoutRole`).
- **Импорт JSON** заранее предупреждает, если файл выключает разделение: «Разделение по зданиям будет выключено: все увидят все здания». Если файл его включает, импорт тоже об этом говорит. Импорт не пройдёт, если `access` в файле не объект.
- **«Сбросить правки»** раздел `access` не трогает и пишет об этом в вопросе. Сброс оформления не должен открыть все здания всем.

## Что разделение не закрывает
- Приложение HA, его история, журнал и обычные дашборды. Это разделение интерфейса Atom Home.
- Страница «Энергия» (для ролей с карточкой `energy`) строится по настройкам «Энергии» Home Assistant. Счётчик ввода без комнаты общий для всего дома, поэтому там видны цифры всего дома. Плитка энергии на главной считает только устройства разрешённых зданий.
- Настройки дома (`config/get`) читает любой вошедший пользователь: кто к какому зданию относится, с какой ролью и до какого дня, видно каждому, кто откроет их через API HA. Это часть решения «только интерфейс».
- Охрана, у которой нет комнаты (Alarmo), общая на весь дом. Её видят все, у кого в роли есть `security`.

## Проверки
- `frontend/tests/access.test.ts`. Тесты в репозитории идут на `node --test`, vitest здесь нет. Проверяется:
  - роль × здание × устройство;
  - временный доступ;
  - несколько зданий и «Все здания»;
  - администратор;
  - `view` и `lights`;
  - планшет;
  - «Кому видно» и перенос в комнату;
  - выключенное разделение;
  - слияние будильников;
  - нормализация, экспорт и импорт;
  - список пользователей, стартовый вариант, копирование и удаление роли;
  - что строки реестра остаются теми же.
- `frontend/scripts/qa-access.mjs` на `scripts/access-fixture.mjs`: три здания и «Двор», администратор и три человека. Проверяется:
  - каждый видит только свои комнаты и свой свет;
  - в режиме «только просмотр» нет ни одного выключателя и ползунка — на страницах, листах и странице комнаты, — и в дом ничего не уходит;
  - переключатель и запоминание выбора;
  - спокойный экран;
  - «Посмотреть глазами» и «Выйти»;
  - выключенное разделение;
  - включение со стартовым вариантом;
  - «нажми всё»: в режиме «только просмотр» сценарий открывает каждую карточку и нажимает каждую доступную кнопку в каждом листе и на странице. Ни одно нажатие не должно быть отклонено: отказы панель считает в `window.__atomAccessRefused`, и каждый отказ значит, что нарисована лишняя кнопка. Если временно отключить запрет в `actionsFor`, сценарий падает — это проверено;
  - панель охраны: у «Сотрудника» её нет, у наблюдателя (`view` + `security`) она только для чтения;
  - привязанный планшет: человек без своего доступа видит на нём здание планшета.

  Скриншоты в светлой и тёмной теме, ширины 1070 и 360. Запуск:
  ```bash
  npm run preview:build && node scripts/qa-access.mjs <папка>
  ```
- `tests/components/atom_home/test_config_guard.py` → `AccessGuard`.
