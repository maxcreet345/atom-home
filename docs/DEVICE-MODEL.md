# Модель устройств: как панель читает чужой дом

Источник: реестры HA (`config/area_registry/list`, `config/device_registry/list`, `config/entity_registry/list`) и `hass.states`. Ни одной ручной привязки: всё выводится по правилам ниже, владелец правит результат в конфигураторе.

## Правила распознавания (`frontend/src/model/kinds.ts`)
| Сущность HA | Вид карточки |
|---|---|
| `light` | свет |
| `switch` (device_class `outlet`) / `switch` | розетка / выключатель |
| `climate`, `fan`, `cover`, `lock`, `vacuum`, `media_player`, `camera`, `weather`, `valve`, `alarm_control_panel`, `person` | одноимённые виды |
| `sensor` с классом температуры/влажности/CO₂/PM/освещённости/давления | **environment** (объединяется по прибору) |
| `sensor` с классом мощности/энергии/напряжения/тока | **energy** (карточка только если есть мощность или энергия; одно напряжение — диагностика) |
| `sensor` без класса | класс угадывается по единице (°C, W, kWh, V, A, lx, ppm, hPa, bar); без единицы — не карточка |
| `binary_sensor` moisture / opening,door,window / motion,occupancy,presence / smoke,gas,CO,safety | протечка / открытие / движение / тревога |
| `binary_sensor` connectivity, running, battery, plug, power, update, problem… | диагностика |
| `update, automation, script, scene, input_*, zone, sun, tts, stt, conversation, event, todo, calendar, notify, device_tracker, remote…` | никогда не карточка |
| `number, select, button, text` и `switch` при более богатом управлении у того же прибора | параметры прибора |
| категория `diagnostic` / `config` | диагностика / параметры |
| платформы `mobile_app, hassio, hacs, backup, cloud, sun, time_date, local_ip, shopping_list` | скрыты целиком |

## Группировка (`discover.ts`)
- Управляемая сущность = отдельная карточка (двухклавишный выключатель — две карточки). Датчики, параметры и диагностика прибора прикрепляются к первой из них.
- Прибор без управления = одна карточка на вид датчиков: environment (температура первой), energy (мощность первой), протечка… Ключи: `e:<entity_id>` для управляемых, `d:<device_id>[:kind]` для датчиков.
- Комната: зона сущности, иначе зона прибора, иначе «Без комнаты» (`none`).
- Конфигурация накладывается после: `mergeInto` переносит управление и показания в другую карточку, `enabled:false` скрывает, `name/roomId/icon/kind/order` переопределяют.

## Экраны
Меню с 1.27.0: Дом · Комнаты · Свет · **Устройства** (вкладки Все · Климат · Уборка · Камеры) · **Энергия** · **Безопасность** · Настройка (администратор). На телефоне — Дом · Комнаты · Свет · Устройства и «Ещё» (Энергия, Безопасность, Настройка). Старые адреса (`#systems`, `#climate`, `#cleaning`, `#camera`, `#energy`, `#security`) работают как раньше; скрытый в «Настройке» раздел ведёт к ближайшему настоящему. Раздел не показывается, если в нём нет устройств.

## «Устройства» — только устройства (v1.27.0)
Одно чистое правило `frontend/src/model/device-list.ts`, тесты `frontend/tests/device-list.test.ts` и `frontend/tests/appliance.test.ts`; таблицу «что показано, что скрыто» для снимка дома печатает `frontend/scripts/devices-shown.mjs`.
- **Показаны:** свет, термостаты и термоголовки, вентиляторы и очистители, пылесос, камеры и звонок, телевизоры и колонки, шторы, замки, краны; карточки кормушки и чайника; прибор, который HA знает только через выключатели (аэрогриль, стиральная и сушильная машины, увлажнитель, поилка, реле вентилятора), — **один раз**, под своим именем, с мощностью на плитке; розетка, которую владелец назвал по прибору («Чайник»).
- **Скрыты:** датчики, счётчики, голые розетки и реле, остальные выключатели прибора (это его настройки), погода, люди, панель охраны (она — «Безопасность»). Скрытое не пропало: оно в комнатах, листах и сводках, а поиск и «Внимание» на «Устройствах» находят и датчики.
- **Прибор** (`frontend/src/model/appliance.ts`): если один из его выключателей и есть его питание (реле вентилятора, «Питание» стиральной машины, насос поилки), нажатие на плитку переключает именно его, как в 1.26.1, а «…» открывает прибор; если такого нет (увлажнитель, аэрогриль, сушилка — их видно по мощности розетки), нажатие открывает прибор. Лист прибора начинается с питания, иначе с мощности, иначе с его состояния; остальные выключатели — в «Настройках» (только администратор, с вопросом). Страница комнаты открывает тот же прибор.
- Группы по порядку: Свет · Климат · Приборы · Камеры · Телевизоры и колонки · Шторы, замки и краны, внутри — по комнатам. Под заголовком комнаты имя не повторяет комнату («Вентилятор» под «Ванная», `nameUnderRoom`), читалка слышит полное имя.
- Большое число в листе говорит мощность единицами панели, как плитка: «0 Вт», «2,4 кВт» (`bigReading` в `ui/format.ts`), а не «0 W» из HA.

## Результат на снимке Criuleni (этап 1)
Без единой привязки распознано: 10 зон; свет 8, климат 7, пылесос 1, камеры 3, протечки 2, кран 1, охрана 2, датчики среды 15, медиа 8, энергия — щит SPM (3 линии по единице kWh/W), розетки/выключатели 19, люди 3. Шум (телефоны, счётчики, permit-join) скрыт правилами; оставшиеся лишние выключатели владелец отключит в конфигураторе (этап 2).

## Второй круг аудита 10.11.2026: плитки, списки, листы
- Устройство без имени (в реестре только entity id, «fan.office_fan») на плитках и в листе называется по виду («Вентилятор»), как в «Настройке» (`shownName` в `ui/format.ts`); id человеку не показывается.
- Плитка, которую нечем переключать (датчик), — одна остановка Tab: сама плитка открывает лист, «Подробнее» остаётся только для указателя (`tabindex="-1"`, `aria-hidden`).
- Лист крана предлагает только возможное: «Открыть» у закрытого, «Закрыть» у открытого; в движении или без данных — обе (`actionsFor`).
- Значок выключенного переключателя в строках листа серый, включённого — зелёный.
- `num` / `numFixed` / время в `stateText` берут форматтеры из кеша `runtime/zone.ts`; `numFixed` для не-числа печатает «—».
