# Модель устройств: как панель читает чужой дом

Источник: реестры HA (`config/area_registry/list`, `config/device_registry/list`, `config/entity_registry/list`) и `hass.states`. Ни одной ручной привязки: всё выводится по правилам ниже, владелец правит результат в конфигураторе.

## Правила распознавания (`frontend/src/model/kinds.ts`)
| Сущность HA | Вид карточки |
|---|---|
| `light` | свет |
| `switch` (device_class `outlet`) / `switch` | розетка / выключатель |
| `climate`, `fan`, `cover`, `lock`, `vacuum`, `media_player`, `camera`, `weather`, `valve`, `alarm_control_panel`, `person` | одноимённые виды |
| `sensor` с классом температуры/влажности/CO₂/PM/освещённости/давления | **environment** (объединяется по прибору) |
| `sensor` с классом мощности/энергии/напряжения/тока | **energy** (карточка только если есть мощность или энергия; одно напряжение — диагностика) |
| `sensor` без класса | класс угадывается по единице (°C, W, kWh, V, A, lx, ppm, hPa, bar); без единицы — не карточка |
| `binary_sensor` moisture / opening,door,window / motion,occupancy,presence / smoke,gas,CO,safety | протечка / открытие / движение / тревога |
| `binary_sensor` connectivity, running, battery, plug, power, update, problem… | диагностика |
| `update, automation, script, scene, input_*, zone, sun, tts, stt, conversation, event, todo, calendar, notify, device_tracker, remote…` | никогда не карточка |
| `number, select, button, text` и `switch` при более богатом управлении у того же прибора | параметры прибора |
| категория `diagnostic` / `config` | диагностика / параметры |
| платформы `mobile_app, hassio, hacs, backup, cloud, sun, time_date, local_ip, shopping_list` | скрыты целиком |

## Группировка (`discover.ts`)
- Управляемая сущность = отдельная карточка (двухклавишный выключатель — две карточки). Датчики, параметры и диагностика прибора прикрепляются к первой из них.
- Прибор без управления = одна карточка на вид датчиков: environment (температура первой), energy (мощность первой), протечка… Ключи: `e:<entity_id>` для управляемых, `d:<device_id>[:kind]` для датчиков.
- Комната: зона сущности, иначе зона прибора, иначе «Без комнаты» (`none`).
- Конфигурация накладывается после: `mergeInto` переносит управление и показания в другую карточку, `enabled:false` скрывает, `name/roomId/icon/kind/order` переопределяют.

## Экраны
Обзор (камера, погода, климат, свет, протечки, воздух, энергия, кнопки владельца, комнаты) · Комнаты · Свет · Климат (все `climate`) · Уборка (`vacuum`) · Энергия (карточки energy **и любые** карточки с показанием мощности — умные розетки, щиты) · Системы (остальное по группам) · Камера и Погода внутри Обзора. Раздел не показывается, если в нём нет устройств.

## Результат на снимке Criuleni (этап 1)
Без единой привязки распознано: 10 зон; свет 8, климат 7, пылесос 1, камеры 3, протечки 2, кран 1, охрана 2, датчики среды 15, медиа 8, энергия — щит SPM (3 линии по единице kWh/W), розетки/выключатели 19, люди 3. Шум (телефоны, счётчики, permit-join) скрыт правилами; оставшиеся лишние выключатели владелец отключит в конфигураторе (этап 2).
