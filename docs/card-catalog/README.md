# Конструктор карточек · этап 1 (20.11.2026)

Задание: `book/06-dashboards/platform-2026/PROMPT-CARD-CATALOG.md`. Ветка `card-catalog` от `cce94cb` (1.31.1). Выпущено как 1.32.0.

## Что сделано

- **Каталог «＋ Добавить карточку»** (только администратор) на главной и в комнате: вкладки «Найдено в этом доме» / «Все карточки», поиск (`Purifier 4`, `Xiaomi`, `zhimi.airp.mb5`), категории и бренды. Из комнаты сначала предлагаются её приборы. Для ненайденной модели показана нужная интеграция HA.
- **Xiaomi Smart Air Purifier 4**: выбор своего прибора, затем только поля карточки — назначение, «обязательно/по желанию», найденный источник, текущее значение, явный внешний датчик. Предпросмотр плитки и листа на данных дома (неактивен, команды не уходят). Название, комната, место: главная, комната или оба.
- **Экземпляр карточки** — `profileInstances[<id>]` в конфиге: свой стабильный id, привязки, имя, комната, размещение. Карточка прибора убирает его старую автоплитку (без дубля). Потерянный датчик даёт сообщение и «Заменить», подмены нет. Пустое необязательное поле скрывает функцию.
- **Отопление · Один центральный термостат** — термостат и, при желании, датчик воздуха для показа (плитка термостата Atom Home).
- **Отопление · Центральный термостат и комнаты** — центральный задатчик, общий режим, общая цель; «＋ Добавить комнату» с головкой, датчиком воздуха, таймером, целями правки и ручного режима. Рисуется действующим экраном «Отопление»; сценарии, котёл и переключатель режима — только если привязаны.
- **Совместимость**: ключ аддитивный, `schemaVersion` остаётся 1. Интеграция отказывает в сохранении панелям без `card_catalog_v1`, если карточки уже есть. Дом без карточек читает и сохраняет всё как раньше, Criuleni без карточки отопления — те же команды.

Переключение режимов отопления на стенде не проверялось — только адресаты команд в тестах.
