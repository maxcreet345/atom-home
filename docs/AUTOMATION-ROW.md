# Строка «Автоматика» в листе устройства — спецификация (AUTO-2 аудита 04.11.2026)

Статус: **одобрено 04.11.2026 («Да, делай»), реализовано в v1.13.0.** Фронт: `ui/sheet.tsx` (`Automations`, `whenRan`), `ui/app.tsx` (`automationsFor`: по сущностям карточки, device_id, затем по комнате с пометкой «по комнате»), `runtime/host.ts` (`automations()`), превью `atomPreview.setAutomations`. Бэкенд: `custom_components/atom_home/automations.py` (`entities_in_automation` / `devices_in_automation` / `areas_in_automation` + обход `raw_config` как запасной путь, `description` из `raw_config`), WS `atom_home/automations`, capability `automations: 1`. QA: `qa-states` «automations — fold «Автоматика (3)»». Макет: `logs/audit-ux/auto2-mock/`. Нужен перезапуск HA после установки.

## Зачем
Житель не понимает, почему свет в коридоре «сам» включился или почему радиатор не греет: панель показывает будильники и таймер выключения света, но не показывает автоматизации HA, которые управляют устройством. Аудит (home-assistant-best-practices, AUTO-2) рекомендует показывать источники автоматики — только чтение, без изменений в HA.

## Что увидит житель
В листе устройства (лампа, термоголовка, кран, розетка, пылесос) под строкой состояния появляется свёртка **«Автоматика (N)»** — как «Настройки (N)» и «Диагностика (N)». Внутри по строке на автоматизацию:

```
⚙  Свет по датчику присутствия            18:40 сегодня   ●
    коридор · включает до 23:00
⚙  Отопление: ночной режим                 вчера, 23:00    ●
    ставит 18° с 23:00 до 06:00
⚙  Отпуск                                   не срабатывала  ○
```

- Название — `friendly_name` автоматизации HA.
- Справа — время последнего срабатывания (`last_triggered`): «18:40 сегодня», «вчера, 23:00», «3 нояб.», «не срабатывала».
- Точка: ● автоматизация включена, ○ выключена (`state: off`) — серым, с подписью «выключена». Это главный сигнал для жителя: «свет не включается сам, потому что автоматика выключена».
- Вторая строка — описание автоматизации из HA (`description`), если владелец его заполнил; иначе пусто. Панель ничего не сочиняет.
- Тап по строке ничего не делает в этапе 1 (только чтение). Включение/выключение автоматизации — не в панели (правило: конфигурацию HA не менять из панели без отдельного решения).

Если автоматизаций у устройства нет — свёртки нет (как сейчас). Нет сообщений вроде «undefined».

## Где ещё
- Плитка термостата на главной: третья строка не трогаем (место); но в листе термостата котла — та же свёртка (отопление по графику, окна, отпуск — те, что мы делали 04.11).
- Раздел «Климат»: ничего нового.

## Как это работает (бэкенд, только чтение)
1. Новая WebSocket-команда `atom_home/automations` (admin не требуется, как `atom_home/state`): бэкенд берёт `hass.data["automation"]` (EntityComponent) → у каждой `AutomationEntity` есть `raw_config` (триггеры, условия, действия, `description`, `alias`), `entity_id`, `state`, `last_triggered`.
2. Из `raw_config` рекурсивно собираются все строки вида `<domain>.<object_id>` в полях `entity_id` (строка или список) и `target.entity_id`; `device_id`/`area_id` в target — тоже сохраняются (панель знает устройства и комнаты по реестру, сможет сопоставить).
3. Ответ: `[{ entity_id, name, description, enabled, last_triggered, entities: [...], devices: [...], areas: [...] }]`, кэш 60 с, пересчёт при событии `automation_reloaded`.
4. Панель запрашивает список один раз после загрузки реестра и обновляет по `last_triggered` из `hass.states` (атрибут автоматизации приходит и так). Сопоставление: автоматизация относится к карточке, если ссылается на любую сущность карточки (primary, controls, metrics), на её `device_id` или только на её комнату (`area_id`) — последнее помечается «по комнате».

Capability `automations: 1` в `atom_home/state`, чтобы панель не показывала свёртку на старом бэкенде.

## Безопасность
Только чтение. Никаких `automation.turn_on/off/trigger` из панели. Описания и названия — из HA, как есть.

## Приёмка
- Превью (фикстура с 3 автоматизациями: включена/выключена/без описания): свёртка «Автоматика (3)», строки с правильными временами, ○ у выключенной; `qa-states` — нет `undefined`/`NaN`.
- Live: лист термостата котла показывает «Отопление: график», «Отопление: окна», «Отопление: отпуск» с реальными `last_triggered`; лист лампы коридора — автоматизацию по датчику присутствия.
- Доступность: свёртка — `details/summary` как у «Диагностики»; точка дублируется словом.

## Оценка
Бэкенд ~60 строк Python, панель ~80 строк TSX + CSS, QA-фикстура, перезапуск HA (новая WS-команда). Один этап.
